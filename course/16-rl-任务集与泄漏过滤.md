# 16 · 任务集与泄漏过滤

上一章把环境搭好了。这一章解决一个更隐蔽的问题：**题目本身可能是假的**。

腾讯混元的后训练岗要求「负责后训练数据合成、设计数据飞轮」，OpenAI 的
Science of Post Training 岗要求「用严谨的科学视角训练生产级模型」。
这一章的内容就是这两条落到地上的样子——而且它是本项目里**最容易被跳过、跳过代价最大**的一环。

---

## 16.1 空洞的环境：一个具体的失败

> **严谨定义**：数据泄漏（leakage）指模型能通过训练语料以外的途径获得答案。
> 在检索环境里，最常见的形式是答案已经存在于模型的参数记忆中。
>
> **大白话**：你出了一道「查资料题」，结果模型早就背过答案。它不查也能答对，
> 于是学会了**跳过工具**。你训出来的不是检索能力，是背书能力——而且你的所有数字都还在涨。

这为什么致命，值得说透：

1. 模型不检索也拿满奖励 → 梯度在奖励「不检索」这个行为。
2. 于是它越来越不检索 → 工具变成装饰。
3. 但 **pass@1 曲线一路上涨**，reward 曲线一路上涨，格式合法率一路上涨。
4. 没有任何下游指标会告警。轨迹看起来干净漂亮。

这是唯一一种「所有仪表都正常、但训出来的东西完全不是你要的」的失败，
所以它在项目风险表里排第一。

HotpotQA 问的是维基百科实体，而每个现代 LLM 都读过维基百科。所以这个风险不是理论上的。

---

## 16.2 怎么测：闭卷问答

做法很朴素：**把题目原样问模型，不给任何工具、不给任何上下文**，
再用**和真实 rollout 完全相同的验证器**打分。

`rl/tasks/leakage.py` 里两个刻意的选择，让这个测量成为**上界**：

```
CLOSED_BOOK_SYSTEM = (
    "你在做一个封闭书本问答测试。只依靠你自己的知识回答，没有任何检索工具。"
    "即使不确定也要给出你最可能的答案，不要回答「不知道」或「无法确定」。"
)
```

1. **提示词鼓励猜，不鼓励拒答。** 如果鼓励「不知道」，测出来的泄漏率会偏低，
   风险被低估。评估风险时，宁可高估。
2. **用强模型测，不用待训练的 1.5B 测。** 强模型背过的题，小模型也可能背过；
   强模型都答不出的题，对小模型是安全的。

### 实测结果

```
模型                  有效判定    泄漏率    bridge    comparison
deepseek-chat           7404      34.7%     27.2%      64.8%
deepseek-v4-flash       3937      28.3%     27.7%      29.6%
并集                     —       49.8%       —          —
```

**近一半的 HotpotQA dev 能被其中一个模型闭卷答对。**

`comparison` 题（「A 和 B 哪个是 X？」）尤其严重——题面就把两个候选都写出来了，
模型只要有一点常识就能选对。真实例子：

```
Q: Who set Nietzche's philosophical novel to music?     → Richard Strauss ✓
Q: What country is home to both Guadarrama National Park
   and Doñana National Park?                            → Spain ✓
```

这两道纯靠世界知识就能答，和检索能力毫无关系。

## 16.3 一个模型不够：泄漏是 (题目, 模型) 的性质

拿同样 300 道题对比两个模型：

| | |
|---|---|
| 两者一致率 | **76.7%** |
| 弱模型覆盖强模型的比例（recall） | 58.2% |
| 弱模型的泄漏集是强模型的子集吗 | **否**——它知道 19 道对方不知道的 |

一致率只有 76.7%，而且**两个集合互不包含**。这推出一个不显然的结论：

> **严谨定义**：泄漏不是题目的固有属性，而是 (题目, 模型) 这个二元组的属性。
>
> **大白话**：「这题会不会被背出来」取决于问谁。所以「用一个模型筛一遍」在方法上是不完整的，
> 正确做法是**取并集**——只要有任何一个模型能闭卷答对，这题就不算检索题。

只用弱模型筛，会漏掉 17% 真正泄漏的题留在数据集里白送奖励。
`rl/cli.py` 的 `tasks split --leakage-file A --leakage-file B` 因此支持多清单取并集。

顺带一个省钱的细节：第二个模型跑的时候加 `--skip-leaked-from A.jsonl`——
第一个模型已经判为泄漏的题，并集里无论如何都要丢，再问一遍是白花钱。
7,405 题于是只需要跑 4,834 题。

## 16.4 两个容易做错的处理

### 空回复是「没有结论」，不是「答不出来」

思考型模型会把输出预算全烧在推理上。实测 `deepseek-v4-flash`
平均每题 **1,291 个 completion token**（一个单词的答案！），尾部超过 4,096 上限，
**18.6% 的题拿不到任何正文**。

我第一版把这些算成「模型不知道」。这是错的：

> **大白话**：模型没说话，不等于它说「我不知道」。这是**测量失败**，不是否定结论。
> 按否定算，就等于把一批可能泄漏的题放进了数据集——正是这道过滤器要防的事。

现在它们记为「未知」：既不计入泄漏率的分母，也不进入覆盖集
（`rl/tasks/leakage.py::LeakageResult.answered`）。

这个坑我踩了两次，第一次更贵：`ANSWER_MAX_TOKENS` 一开始按**均值**（515）定成 1200，
结果 22% 的题撞到上限返回空。**按均值定尾部参数**是个通用错误，值得记住。
（改大几乎免费：按实际生成的 token 计费，提前结束的题不会因为上限高而变贵。）

### 覆盖不全就丢弃

于是产生第二个问题：一部分题被两个模型复核过，一部分只被一个复核过。

> **大白话**：数据集里一半的题过了两道安检，另一半只过了一道。
> 那另一半就更可能藏着泄漏题，而**在它上面测出的任何指标都会被抬高**。

`--require-coverage` 只保留**所有过滤器都实际复核过**的题。集合上就是：

```
covered = (泄漏并集) ∪ (各过滤器有效集的交集)
```

代价是少 897 道题，换来过滤强度一致。这是自检里专门断言过的一段
（`rl/checks/rl_check.py` 有对应阶段），因为集合运算写错的方式很多、症状很轻。

## 16.5 「一次检索即可解」：只打标签，不丢弃

另一道纯本地、零成本的过滤器：把问题原文直接塞进 BM25，看 gold 文档会不会一次全出来
（`rl/tasks/adversarial.py::one_query_solvable`）。

实测：**48.3% 的题一次检索就能拿到全部 gold**，而 95.7% 能拿到至少一篇。
这个差值就是「第二跳」真正存在的部分。

但这些题**只打标签，不丢弃**，理由和泄漏题完全不同：

> **大白话**：它们是**简单**，不是**空洞**。一次检索能找到证据，但仍然需要构造查询、
> 读结果、综合作答——这些都是真实能力。丢掉会白扔四成数据。

而且静态丢弃在 GRPO 下没必要：一道题变得太简单，组内奖励方差就会归零，
advantage 恒为 0，它**自动**停止贡献梯度（第 19 章的在线难度课程）。
让算法自己淘汰，比一次性拍死更准。

评测时按这个标签**分片报告**，避免用总体数字掩盖是哪一半在动。

## 16.6 最终漏斗

```
原始题目                7405
泄漏过滤器              chat ∪ v4-flash
− 闭卷可答（泄漏）丢弃   3684  (49.8%)
− 覆盖不全丢弃           897  (12.1%)
= 保留                  2824
  其中「一次检索即可解」  1158  (41.0%)  —— 只打标签，不丢弃

train 1908 · dev 457 · test 459    按 qtype 分层，各自记 sha256
```

**这张漏斗表是本项目最该拿出去的单一产出物。** 它同时证明三件事：
你知道数据可能是假的、你去量了、你按量出来的数字做了取舍。
几乎没有人在简历项目里做这一步。

### 一个必须解释的副作用

`comparison` 题从原始的 20.1% 降到切分后的 12.0%。这不是分层的 bug——
是因为 comparison 的泄漏率（64.8%）远高于 bridge（27.2%），所以被过滤掉的比例更大。
这是过滤器的**正确**后果。

能预见并解释这种副作用，和「发现分布变了但不知道为什么」，是两个层级。

---

## 16.7 切分本身的两个细节

**按 `qtype` 分层，不按 `level`。** 因为 HotpotQA dev 的 7,405 道题
**全部是 `level=hard`**——这是我查过的，不是假设的。真正有变化的轴是
bridge(5,918) vs comparison(1,487)，两者行为差别够大，切分漂了 dev 和 test 就不可比。

**三个 split 各自记 sha256**，理由和语料一样：一个数字只在「某个具体切分」上有意义。

---

## 16.8 本章小结

- 泄漏是唯一一种「所有仪表正常、训出来的东西完全不对」的失败，所以排风险第一位。
- 测法：闭卷问答 + 同一个验证器；提示词鼓励猜、用强模型，让结果成为**上界**。
- 实测近一半 HotpotQA dev 泄漏；泄漏是 (题目, 模型) 的性质，所以必须取并集。
- 空回复是「未知」不是「否定」；覆盖不全的题要丢，否则过滤强度不一致。
- 「一次检索可解」只打标签——它简单但不空洞，交给在线课程自然淘汰。
- 漏斗表是最值得拿出去的产出物；`comparison` 占比下降是正确的副作用，要能解释。
