# 联网查证

## 什么时候用

用户问的事情涉及**你不确定的外部事实**（版本号、价格、新闻、某个库的当前 API），
或者答案会随时间变化。纯粹的推理、工作区里已有的文件、常识性问题都不需要走这套流程。

## 步骤

1. **先搜索，不要直接猜 URL。** 用 `web_search` 检索，把问题拆成 2-3 个关键词组合，
   而不是把用户的整句话原样丢进去。
2. **挑来源。** 优先官方文档、项目仓库、一手公告；论坛与二手转述只用来交叉验证。
   搜索结果的摘要**不能当作答案**，它经常是过时或被截断的。
3. **抓原文。** 对选定的 1-3 个链接用 `web_fetch` 读正文。抓取失败就换一个来源，
   不要基于搜索摘要硬答。
4. **交叉验证。** 关键数字（版本、日期、价格）至少要有两个来源一致，或者来自官方。
5. **写结论。** 格式：结论在前，证据在后，每条事实后面跟来源链接。

## 硬性要求

- **拿不准就说拿不准。** 抓取全部失败时，如实说明「没能查到」，并说清你试过什么。
  编一个看起来合理的答案比承认查不到更糟。
- **区分「原文这么写」和「我的推断」**，不要把后者写成事实。
- 时间相关的问题先调 `current_time` 拿准确时刻，不要去网上查时间。
