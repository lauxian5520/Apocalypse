# 产出报告文件

## 什么时候用

用户要的是一份**可以留存、可以给别人看**的产物（分析报告、调研纪要、方案说明），
而不只是对话里的一段回答。判断标准：内容超过屏幕一屏，或者用户说了「写成文件」「整理一份」。

## 步骤

1. **先列提纲**，用 `todo_write` 记下要写的几节，让用户看得到进度。
2. **命名文件**：`<主题>-report.md`，全小写、用连字符，不要带日期
   （改一版就多一个文件，反而找不到最新的）。
3. **写入**：用 `write` 一次写完整篇，不要分多次追加——中途失败会留下半截文件。
   内容超过 300 行就拆成多个文件，用一个 `index.md` 串起来。
4. **读回自检**：写完用 `read` 把文件读一遍，确认没有截断、没有占位符残留
   （`TODO`、`待补充`、`...`）。
5. **回话**：告诉用户文件名和它的结构，正文不要在对话里重复一遍。

## 报告结构

```markdown
# 标题

## 结论
（三到五句话说清最重要的判断，让人只读这一节也能用）

## 依据
（支撑结论的事实，一条一段，有来源就标来源）

## 细节
（展开说明，可分小节）

## 存疑
（没查清的、有争议的、需要人确认的。这一节空着比编满好）
```

## 硬性要求

- **「存疑」一节不能省。** 一份看起来什么都确定的报告通常是漏掉了不确定的部分。
- 所有路径都相对工作区，写文件前不需要建目录（`write` 会建）。
- 工作区有配额，报告里不要嵌入大段原始数据，引用文件名即可。
